# 0026. DevEx synthetic corpus + deterministic generator

- **Phase / milestone:** Phase 3 — second vertical (DevEx Copilot), Unit 1
- **Issue:** —
- **Status:** approved (autonomous mode; decisions recorded here)

## Problem

The DevEx vertical needs data: CI/CD pipeline logs, PR diffs, and ticket
history (CAPABILITIES vertical B). Real exports raise the same problems SALT
did (spec 0010): licensing, redistribution, clone-and-run. The same answer
applies — a **deterministic synthetic corpus with realistic shapes**, under
`data/devex_synthetic/`, generated by a committed stdlib script. The corpus
must contain *genuine* difficulty (entity-resolution variants, a recurring
failure, cross-source references), not planted-easy cases.

## Acceptance criteria

- [ ] `scripts/generate_devex_synthetic.py` (pure stdlib, fixed seed) writes
      `data/devex_synthetic/`: `components.csv`, `owners.csv`, `pipelines.csv`,
      `runs.csv`, `tickets.csv`, `prs.csv`, `logs/run_<id>.log` per run,
      `prs/<id>.diff` per PR, `MANIFEST.json`, `README.md`. Byte-for-byte
      reproducible (committed output == regeneration).
- [ ] **Recurrence anchor:** runs `R-0987` and `R-1042` (payments pipeline)
      fail with the same error signature, which also appears verbatim in
      resolved incident ticket `DEVEX-187`; `R-1041` on the same pipeline
      **passes** (the "why did it fail" refusal target).
- [ ] **PR↔ticket references:** PR descriptions cite their motivating ticket
      ("Fixes DEVEX-204"); one PR deliberately cites none.
- [ ] **ER difficulty with measured outcomes:** `owners.csv` names services
      in variant forms — exact/punctuation/typo variants that resolve at the
      0.85 threshold, plus `checkout-svc` (similarity 0.846 — a *named
      near-miss*) and `notif-svc` (0.429 — a named far miss) that do not.
- [ ] A second recurring signature on another pipeline (search), so
      recurrence is a class, not a one-off.
- [ ] Tests: regeneration determinism, committed-data equality, FK integrity
      (runs→pipelines, pipelines/tickets→components, PR commits↔runs where
      intended), every failed run's log contains an `ERROR` line, the
      recurrence signatures appear where claimed.

## Scope

**In:** the corpus, the generator, corpus-invariant tests, NOTICE/README.
**Out:** ingesters (Unit 2), graph assembly (Unit 3), any engine change.

## Eval impact

None yet — data only. This corpus is what the DevEx battery (specs
0029–0033) will measure; its planted misses are how DevEx coverage starts
honestly below 1.0.

## Risks / open questions

- Component names must keep distinct services below the resolution threshold
  (max measured cross-service similarity 0.78) — pinned by a test in Unit 3.
- Log chunking relies on blank-line-separated job sections (the engine's
  `chunk_text`); the log format is written to that contract on purpose.
